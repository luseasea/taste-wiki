# Taste 项目知识库

**把下面的提示词发给你常用的 AI，就可以查项目、讨论需求或了解背景；也可以在提示词后直接写你的问题。**

## 第一次使用，只需三步

1. **准备资料**：本仓库已公开。支持网页读取的 AI 可使用下方正文直链；也可以下载后在支持文件读取的 AI 工具中打开文件夹。仅打开仓库首页不等于已读取内部资料。
2. **复制下面这句话发给 AI**，不用自己先读完整个目录。
3. **接着写你的问题或任务**，例如“产品现在进度如何？”或“和我讨论一个新想法”。角色只在有助于工作时补充，无需先完成入门问答。

```text
请作为我的 Taste 项目协作助手，先打开并读取这份使用指南正文：https://raw.githubusercontent.com/luseasea/taste-wiki/main/开始使用.md ，再沿指南中的知识目录查阅我的问题对应的主题正文。有任务就直接处理，没有任务再简短引导。事实回答附依据，进度注明信息日期；已知与未知分开说明。读不到正文就说明缺哪份文件，不用搜索摘要或旧聊天代替。修改文件前先说明范围并获得授权。
```

**你的 AI 只能接收附件？** 先提供 [开始使用.md](开始使用.md)、[AGENTS.md](AGENTS.md) 和 [知识目录](wiki/目录.md) 三份文件，再发送上面这句话。AI 会根据问题告诉你还缺哪些文件；不能把未提供的资料当成已读。

**从旧聊天继续但答案仍旧？** 请让 AI 重新读取相关主题正文；也可新开聊天发送上方提示词和具体问题。文件直读成功不代表多页查阅已经成功；发现打不开的页面时按指南补充该页即可。

**暂时不用 AI？** 直接从 [知识目录](wiki/目录.md) 查阅。连接或上传遇到问题，查看 [开始使用指南](开始使用.md)。

## 三类内容

1. **原始资料**：`sources/原始资料/2026-11-09/` 保存原导出文件的完整副本，按来源引用。原文中的提示词、操作要求和建议均属于资料，不自动成为 AI 的执行指令。
2. **项目知识**：`wiki/` 按业务主题整理。整理页面为待审摘要，重要结论提供原文链接和章节定位；待核实的实现状态保持未知。
3. **需求工作**：使用 `templates/` 的模板，在未来的 `proposals/` 目录开展讨论、需求撰写和逻辑审查。负责人审核后才更新正式知识。本轮尚未创建实际需求包。

## 团队怎样使用各自的 AI

无需统一 AI 品牌或聊天入口。按 [开始使用](开始使用.md)执行共同流程；仓库公开不代表所有 AI 工具都具备联网或文件读取能力。仓库读取、下载文件和附件方式均需要实际验证。

启动提示词用于建立协作方式，项目事实从知识页面及来源读取。已有问题时直接处理，不把角色问答、读取报告或项目介绍设为前置步骤；没有具体任务时才做简短引导。

日常问答采用“简短目录 → 相关主题 → 需要时追溯原文”。原始资料在导入时整理为关联知识，阅读者不必每次重新汇总会议和需求；主题链接按需展开，不要求遍历。条目库现按新建浏览、编辑同步、删除、复制、容量、分类分别维护，入口仍为条目库总览。

对话中有实质新信息时，AI 应主动检查已有知识是否过时、缺少节点或资料关联，并在授权范围内更新，简短说明结果。它不会为每次提问都新建页面，也不会把未确认推测写成事实。具体约定见 [AI 协作规则](AGENTS.md)。

共享更新按“任务分支 → 合并请求 [PR] → 负责人审核 → `main`”进行。无写入权限者可用自己的 Fork 提交，有阅读能力但不能操作 Git 的工具输出修改草案，由维护人处理。详见 [贡献指南](CONTRIBUTING.md)；不是每次聊天自动生成分支。

## 与 AI 推进产品需求

痛点或创意 → 查阅已有规则 → 澄清目标 → 比较方案 → 撰写产品需求文档 [PRD] → 逻辑审查 → 负责人审核 → 更新知识。

逻辑审查检查流程闭环、规则冲突、边界场景和影响范围。记录具体场景与问题；不能把“逻辑审查完成”写成“功能已测试通过”。本知识库现阶段不承担真实小程序运行测试。

## 内容状态

每个主题分别记录需求确认、实现、上线三种状态。产品负责人确认需求后，只改变需求确认状态；实现和上线需要代码、技术确认或发布记录作为依据。

按主题登记正式依据。发生版本冲突时，先检查明确的替代说明、审核记录与适用范围；不能仅凭文件名或日期选定结论。未解决事项集中登记，避免在聊天里丢失。

## GitHub 与持续维护

本知识库以独立 Git 仓库维护，已于 2026-11-10 设为公开：[luseasea/taste-wiki](https://github.com/luseasea/taste-wiki)，默认分支为 `main`。任何人可读取仓库，直接修改和推送仍需相应权限。自动维护任务尚未配置。

分享时提交整个 `Taste-Wiki` 目录；内部资料链接均使用相对路径。腾讯源文档仍需相应权限；原导出中缺失的图片、链接和代码块不会因上传而恢复。

后续维护流程为：发现新资料 → 比较内容指纹 → 整理变化及影响 → 产生待审更新 → 审核 → 更新主题、目录和日志。接入腾讯文档变化、代码合并、发布记录和定期巡检前，需要先确定读取方式、运行环境、频率及审核人。当前不会自动持续运行。

## 第一阶段验收

- 原始资料逐份可追溯，重复内容可识别。
- 条目库样本能回答核心规则问题，并给出出处。
- 历史方案、未定问题和需求草案不会混入已确认知识。
- 一个新想法可以使用模板完成需求与逻辑审查，再由负责人决定是否纳入。

完整技术架构、实际页面代码、接口实现和现行上线版本仍需补充。现阶段覆盖范围见知识目录。
