## 一、技术架构概述

### 1.1 为什么不用 LLM 直接分类？

根据 7.11 技术讨论结论，AI 自动分类和 AI 智能推荐是**两种不同的技术方案**：

| 维度 | AI 自动分类 | A I 智能推荐 |
| --- | --- | --- |
| 技术方案 | Embedding + 向量化 + 召回策略 | 普通大模型（DeepSeek） |
| 复杂度 | 高（需训练/微调） | 低（Prompt 即可） |
| 成本 | 较高 | \~240 元/年 |
| 用户反馈信号 | 长按挪动 = 增强训练 | 无在线学习 |

## 二、四分类定义体系

### 2.1 分类标准

| 分类 | Icon | 定义 | 典型示例 |
| --- | --- | --- | --- |
| **美食** | 🍽️ | 可食用/饮用的产品或场所 | 餐厅、咖啡馆、奶茶店、小吃摊、甜品店、酒吧、食材、菜式、零食 |
| **玩乐** | 🎯 | 娱乐/体验/运动/旅行相关 | 景点、展览、演出、音乐会、密室逃脱、徒步路线、健身房、游戏 |
| **好物** | 🛍️ | 实体商品/物品/产品 | 电子产品、书籍、服饰、美妆、家居用品、数码配件、文创产品 |
| **其他** | 📦 | 无法归入以上三类 | 抽象概念、服务、人物、App、影视作品、音乐专辑、宠物 |

### 2.2 边界情况处理规则

以下是容易产生歧义的边界情况，需特别处理：

| 边界场景 | 归类 | 判断依据 |
| --- | --- | --- |
| 咖啡店 | **美食** | 核心价值是可饮用产品（咖啡），非游玩场所 |
| 猫咖/狗咖 | **玩乐** | 核心价值是互动体验，饮品为附属 |
| 网红打卡点（餐厅） | **美食** | 本质是餐厅，打卡为附属属性 |
| 网红打卡点（景点） | **玩乐** | 本质是景点/拍照点 |
| 书店 | **好物** | 核心是售卖商品（书籍），非阅读体验 |
| 图书馆 | **玩乐** | 核心是阅读体验/学习空间，非购买商品 |
| 火锅底料 | **美食** | 食材类归美食 |
| 厨具/餐具 | **好物** | 工具类归好物 |
| 外卖平台 App | **其他** | 服务/平台类，非具体食物 |
| 健身私教课 | **玩乐** | 运动体验类 |
| 运动鞋 | **好物** | 实体商品 |
| 演唱会 | **玩乐** | 演出/活动 |
| 专辑 CD | **好物** | 实体商品 |
| 音乐专辑（数字） | **其他** | 数字内容 |
| 宠物用品 | **好物** | 实体商品 |
| 宠物店 | **玩乐** | 互动体验场所 |

### 2.4 POI 辅助分类规则 🆕

当条目名称/描述不足以判断时，POI 位置信息作为辅助信号：

| POI 类型关键词 | 倾向分类 | 置信度加成 |
| --- | --- | --- |
| 美食街/美食广场/大排档/餐饮/食堂 | 美食 | +0.15 |
| 购物中心/商场/百货/奥特莱斯/步行街 | 好物 | +0.10 |
| 景区/公园/游乐园/博物馆/体育馆/剧院 | 玩乐 | +0.15 |
| 写字楼/创意园/产业园/科技园 | 无倾向 | 0 |
| 机场/高铁站/火车站/小区/住宅/社区 | 无倾向 | 0 |

\POI 名称直判规则\（仅在条目名称/描述信息不足时触发）：

| POI 名称包含 | 直接判定 | 置信度 |
| --- | --- | --- |
| XX餐厅/XX饭店/XX酒家/XX馆子/XX咖啡/XX奶茶/XX烘焙 | 美食 | 0.90 |
| XX乐园/XX景区/XX公园/XX博物馆/XX体育馆 | 玩乐 | 0.90 |
| XX商场/XX百货/XX专卖店/XX旗舰店 | 好物 | 0.85 |

> > \关键场景\：同一条目名称在不同 POI 下可能归入不同分类。例如「全家便利店」在写字楼B1（餐饮属性强）→ 美食，在小区内（日用品属性强）→ 好物。POI 是解决这类歧义的核心信号。

## 五、置信度阈值与兜底策略

### 5.1 置信度分级

| 置信度 | 处理方式 |
| --- | --- |
| ≥ 0.75 | 自动归类，不提示用户 |
| 0.50 \~ 0.75 | 自动归类，但标记「低置信度」，后续可让用户确认 |
| \ | 自动归入「其他」，标记待用户手动调整 |
| 最高两类分数差 \ | 视为模糊，归入「其他」兜底 |

### 6.2 锚点向量更新策略

- **实时更新**：单次纠错不立即更新（防止噪声）

- **批量更新**：每累计 N 次同类纠错后（建议 N=20），重新计算锚点向量

- **更新方式**：将该条目的 Embedding 加入正确类别的锚点集合，重新计算均值

- **异常过滤**：同一用户短时间大量纠错 → 标记异常，不参与训练

## 📖 使用说明

### 后端集成步骤

1. **选择 Embedding 模型**：建议使用 text2vec 或 BGE 中文模型（开源、免费、中文效果好）

1. **预计算锚点向量**：启动时按 4.1 的锚点文本计算四分类锚点向量，缓存到内存

1. **接收新条目**：按 3.2 模板构造文本 → 调用 Embedding → 按 4.3 计算相似度 → 返回分类

1. **存储分类结果**：将分类结果写入条目的 `category` 字段

1. **收集纠错数据**：按 6.1 格式记录每次用户手动调整

1. **定期更新锚点**：按 6.2 策略更新

### 分类准确率目标

- 一期目标：≥ 85%（基于 ≥200 条测试数据集）

- 二期目标：≥ 92%（用户纠错反馈后）

## ⚙️ 参数说明

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| Embedding 模型 | BGE-large-zh-v1.5 | 中文 Embedding 模型，可替换 |
| 置信度阈值（高） | 0.75 | 高于此值直接归类 |
| 置信度阈值（低） | 0.50 | 低于此值归入「其他」 |
| 模糊判定差值 | 0.10 | 最高两类分差小于此值视为模糊 |
| 批量更新阈值 N | 20 | 累计 N 次同类纠错后更新锚点 |
| 文本截断长度 | 100 字 | 条目描述最大字符数 |

## 🔄 变体建议

### 变体 1：增加图片 Embedding（二期）

- 当条目包含图片时，使用 CLIP 等多模态模型同时编码文字+图片

- 文字向量和图片向量加权融合（建议文字权重 0.7，图片权重 0.3）
### 变体 2：细分类别（三期）

- 当用户量增大后，可在四分类下增加二级分类

- 例如：美食 → 中餐/西餐/日料/甜品/饮品/小吃

- 方法：对每个一级分类内部的条目做聚类，自动发现二级分类

### 变体 3：个性化分类（远期）

- 记录每个用户的分类偏好

- 同一用户倾向于把咖啡归入「玩乐」（探店体验）而非「美食」

- 引入用户级偏置向量，与全局锚点加权融合
