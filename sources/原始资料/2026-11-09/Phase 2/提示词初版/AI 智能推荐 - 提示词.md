# AI 智能推荐 - 提示词工程文档

> **版本**: v0.1 初版 | **日期**: 2026-07-16 | **作者**: 小鲁 + Claude
> **技术方案**: 普通大模型（DeepSeek），Prompt Engineering
> **触发场景**: 榜单编辑页 → 点击「为你推荐」按钮

---

## 一、功能概述

### 1.1 产品定位

在用户创建/编辑榜单时，根据榜单的标题、类别和已入选条目，智能推荐用户条目库中可能相关的条目，帮助用户快速填充榜单内容。

### 1.2 合规要求（去 AI 化）

微信小程序个人主体不支持 AI 功能展示，因此：

- 按钮文案：**「为你推荐」**（非「AI 推荐」）

- Icon：渐变色 ✦ 风格（非 AI/机器人图标）

- Loading 文案：「正在为你推荐...」

- 不展示推荐理由/匹配度分数

- 不展示「AI」相关字样

### 1.3 技术方案

- **模型**：DeepSeek（或其他国产大模型）

- **成本**：约 240 元/年（一周几块钱）

- **调用方式**：云端 API，后端代理（不从小程序直接调用）

- **缓存策略**：同一榜单未变化时，5 分钟内不重复请求

## 二、System Prompt（系统提示词）

### 2.1 完整 System Prompt

> > \🆕 POI 补充（v0.2）\：推荐原则新增第 \3\ 条——\地理位置相关\：如果榜单标题包含地名（如「广州」「天河」），优先推荐同一城市/区域的条目；跨城条目不推荐。匹配层级：同商圈 +0.30 / 同区域 +0.25 / 同城市 +0.20 / 无地名不加成 / 不同城归零。
>

### 2.2 System Prompt 设计说明

| 设计要素 | 说明 |
| --- | --- |
| 角色定位 | 「品味推荐助手」——去 AI 化，强调品味匹配 |
| 任务描述 | 精炼、明确、无歧义 |
| 推荐原则 | 五条原则覆盖了匹配、多样、去重、质量四个维度 |
| 输出格式 | JSON 结构化输出，便于后端解析 |
| 限制条件 | 最多 20 个、宁缺毋滥 |

## 三、User Prompt（用户提示词模板）

### 3.1 完整 User Prompt 模板

### 3.2 模板变量说明

| 变量 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `{{rank_title}}` | string | 榜单标题 | 「广州必喝咖啡馆 TOP10」 |
| `{{rank_category}}` | string | 榜单类别 | 「美食」 |
| `{{selected_items}}` | array | 已入选条目列表 | \[\{name: "喜茶", description: "..."}] |
| `{{item_library}}` | array | 用户条目库全部条目 | \[\{item\_id: "...", name: "...", description: "...", category: "..."}] |

### 3.3 条目库数据量控制

- 理想情况：用户条目库 ≤ 275 条，全部传入

- 极端情况：若条目库过大（如 > 500 条），先做一层粗筛：


 筛选与榜单类别相同的条目（如榜单是美食类，先只看美食类条目）

 - 如果仍超过 300 条，随机采样至 300 条传入

- 传入条目的字段：仅传 `item_id`、`name`、`description`（截断至 50 字）、`category`

## 五、推荐结果处理（前端）
### 5.1 结果分级展示

| 场景 | 行为 |
| --- | --- |
| 有推荐结果 | 逐个弹出（staggered reveal），推荐条目置顶 + 分割线 + 下方全部条目 |
| 推荐中 | 骨架屏（3-6 卡片）+「正在为你推荐...」 |
| 无推荐结果 | 提示「暂未找到匹配的条目，去新建一个吧」+ 新建按钮 |
| 接口超时（>5s） | 降级展示全部条目（不置顶），toast「推荐暂时不可用」 |
| 接口报错 | 降级展示全部条目（不置顶），静默失败，不打扰用户 |

### 5.2 推荐条目置顶规则

- 推荐条目在「全部条目」上方，中间用分割线隔开

- 推荐条目已选中 → 在下方「全部条目」中灰掉不可选

- 下方「全部条目」按四分类可展开/收缩，按时间排序

- 推荐+手动折叠面板：同时只展开一个

### 5.3 缓存策略

- 同一榜单（title + category + selected\_items 未变化）→ 5 分钟内缓存复用

- 用户修改榜单标题/类别/增删已选条目 → 清除缓存，允许重新请求

- 切换页面再回来 → 缓存仍有效（时间窗口内）

## 📖 使用说明

### 后端集成步骤

1. **部署模型**：部署 DeepSeek API 或代理到国内可访问的端点

1. **构造 User Prompt**：按第三章模板，填入榜单信息 + 条目库数据

1. **调用模型**：将 System Prompt + User Prompt 发给模型 → 解析 JSON 输出

1. **返回前端**：仅返回 `item_id` 列表（不返回 relevance 分数），前端根据 ID 查本地数据渲染

1. **异常处理**：JSON 解析失败 → 重试一次 → 仍失败则返回空数组（降级）

1. **日志记录**：记录每次推荐请求的输入/输出/耗时，用于后续调优
### 推荐质量目标

- 推荐准确率（用户实际选择了推荐条目）：≥ 60%

- 推荐覆盖率（有推荐结果的请求占比）：≥ 80%

- 平均响应时间：\

**响应**：

- 后端负责：查用户条目库、构造 Prompt、调用 LLM、解析结果

- 前端负责：根据 `item_ids` 查本地数据、渲染 UI、处理各状态
