# Epic 6：口令码与外部增长

**优先级**：P0 | **User Story**：US-20 \~ US-22 | **最后更新**：2026-07-12

## 目标

分享时自动生成自然语言口令码，用户可通过统一分享弹窗选择微信好友、图片海报或口令码进行分享。识别口令采用**双流程设计**：登录用户 Happy Pass 静默识别剪贴板（识别到弹卡片，识别不到无感），未登录用户或静默失败/权限被拒时，通过首页左上角「识别口令」按钮打开手动输入弹窗兜底。这是 Phase 2 增长破圈的核心通道。

## US-20 生成口令码

**As a** 榜单创建者
 **I want** 我的榜单自动拥有一个口令码
 **So that** 我可以把榜单分享到小红书/抖音/微信群等外部平台

### Acceptance Criteria

- 榜单创建时自动生成口令码

- **格式**：`来看[用户名前6字][字母1字母2]的[形容词]品味[字母3字母4]`


 形容词池（5个）：高雅 / 超绝 / 独到 / 封神 / 神仙，随机取1个

 - 随机字母4位：a-z 大小写敏感，前后各插2位，共 52⁴ ≈ 730万 种组合

 - 总组合数 = 5 × 52⁴ ≈ 3,650 万种，接近三方平台防扫描下限

 - 前后分开插入的位置本身也是加密因素

 - 全自然语言，零导流特征

 - ⚠️ 7.11 会议决策：原 2 位字母仅 3,380 种组合，可被暴力枚举，故加密至 4 位

- 用户名：取微信昵称前6个字符；纯 emoji 昵称过滤取汉字/字母，都没有则用「Taster」

- 用户修改昵称后同步更新口令码的用户名部分，不一次定死

- 口令码永久有效；一个榜单可能对应多个口令码（用户名变更或多次生成），每次形容词和字母组合随机

- Phase 1 已有榜单需要批量补生成口令码（后端数据迁移）

- **后端需确保口令码唯一性**，不重复

> ✅ 口令码格式已与技术侧确认，方案没问题。技术侧要求保证口令码不重复即可。

## US-21 分享榜单
**As a** 榜单创建者
 **I want** 点击分享按钮，选择不同方式分享我的榜单
 **So that** 我可以通过微信好友、图片海报、口令码等多种途径传播榜单

### Acceptance Criteria

- 榜单编辑页右上角提供**统一分享按钮**（分享 icon），点击后弹出半屏分享弹窗，包含三种分享方式：

- **微信好友**：点击后触发微信小程序原生分享（`shareAppMessage`），与通过小程序右上角三点菜单分享给微信好友效果一致

- **图片海报**：点击后跳转到图片分享页（`pages/share/index`），复用 Phase 1 图片海报生成功能

- **口令分享**：点击后自动生成口令码并复制到系统剪贴板


 口令生成成功 → 半屏弹窗自动消失 → toast 提示「已复制，识别口令即可找到你的榜单！」

 - 口令生成失败 → toast 提示「复制失败，请重试」

- **分享卡不写口令码**（口令码和分享卡解耦，防止外平台限流）

- **不提供文案模板**（有被平台识别为导流话术的限流风险）

## US-22 识别口令码进入榜单

**As a** 在小红书/抖音/微信群看到朋友分享口令码的用户
 **I want** 通过静默自动识别或手动输入口令码找到榜单
 **So that** 我能快速看到朋友的榜单，即使剪贴板读取受限也有兜底方式

> 🔴 2026-07-11 会议决策：口令识别改为「登录用户 Happy Pass 静默 + 未登录/失败/主动触发走手动输入」双流程。静默识别成功 → 弹卡；静默失败 → 完全无感；手动输入错误 → 明确报错并提示格式。必须保留独立于剪贴板权限的手动输入兜底入口。

###

- 用户协议页面（`pages/agreement/index`）和隐私条款页面（`pages/privacy/index`）内容需同步更新为在线文档「🔒 隐私与协议」文件夹下的最新版本

> 【腾讯文档】用户协议（前端展示）[https://docs.qq.com/aio/DYmpvUERTWXRsQ2ZR]()
> 【腾讯文档】隐私条款（前端展示）[https://docs.qq.com/aio/DYmdsWXJzWm1FTGRF]()

- 微信公众平台后台「剪贴板用途」已填写并通过审核

- 用户首次登录时已手动同意协议内容，后续进入小程序不再弹出隐私保护弹窗，直接进入即读取剪贴板

- 若微信侧对剪贴板读取有硬性弹窗要求，可添加设计稿中的隐私保护说明弹窗（见 Figma 设计稿）

### 流程A：静默识别

**前置条件（三者同时满足才走此流程）**：① 用户已登录（已同意协议）；② 剪贴板读取权限拿到；③ 剪贴板内容符合口令码格式且能匹配到榜单。
- 用户进入小程序时，自动读取系统剪贴板内容，全程静默（无 toast、无 loading）

- 若识别到符合口令码格式的内容 → 弹出口令码识别结果弹窗，展示榜单名称 + 创建者用户名

- 已弹过的口令码需本地缓存去重，避免用户切后台再进来反复弹同一个卡片

- 点击弹窗中「查看榜单」按钮 → 跳转至榜单查看页（`pages/view-list/index`）

- 若剪贴板为空或未识别到口令码 → **没有任何反应**（全程无感，不打扰用户）

### 流程B：手动识别

触发场景：① 未登录用户（无剪贴板权限）；② 拿不到剪贴板权限（微信协议变更/用户拒绝）；③ 用户主动想识别。**不强制引导登录**（多多要求：初次接触用户不能被登录墙劝退）。

- 点击首页左上角「识别口令」按钮 → 弹出**手动输入弹窗**，包含：


 输入框（支持长按粘贴，键盘回车即触发识别）

 - 「开始识别」按钮（点击按钮或键盘回车均可触发识别）。识别开始后按钮**置灰**、文字变为「识别中」，输入框不可编辑

 - 输入框下方蓝色链接文字「查看口令码规则」→ 点击弹出中心弹窗解释口令码格式和正确用法（防止用户输入错误后怀疑是系统问题）

- 点击「查看口令码规则」→ 弹出中心弹窗，展示口令码规则说明（如下），用户点击「知道了」关闭

> > **口令码规则（面向用户展示）**
>
>
> > 口令码是 Taste 用户在分享自己的榜单时自动生成的一段文字。把它复制发送到小红书、抖音、微信群，朋友就能通过它找到你的榜单。
>
>
> #### 口令码长什么样？
>
> > 格式：「来看」+ 用户名 + 两个字母 + 「的」+ 一个形容词 + 「品味」+ 两个字母
>
>
> > 例如：来看小明ab的高雅品味cD
>
>
> #### 怎么用？
>
> 1. 复制朋友分享的完整口令码（一整段文字）
>
> 1. 粘贴到输入框中，点击「开始识别」
>
> 1. 识别成功后会直接跳转到对应的榜单
>
> #### 为什么识别不出来？
>
> - 请确认口令码是否复制完整——前后不要多字、不要少字
>
> - 字母大小写必须完全一致（a 和 A 是不同的）
>
> - 一个口令码只对应一个榜单，如果提示「未找到」，可能该榜单已被删除

- 识别开始后，顶部 toast 显示「识别口令码中…」（覆盖按钮置灰 + 请求等待的时间窗口）

- **识别成功** → 关闭手动输入半屏弹窗 → **直接跳转**至榜单查看页（`pages/view-list/index`），不复用流程 A 的卡片弹窗

- **识别失败 → 必须明确报错**：


 格式不匹配 → toast「口令码格式有误」

 - 格式对但榜单不存在 → toast「未找到对应的榜单，请检查口令是否完整」

###

- 未登录用户不走静默识别（没有剪贴板权限）

- 未登录用户可通过左上角按钮走手动输入流程（流程 B），输入成功即可打开榜单查看页

- **不强制引导登录**（多多明确要求：口令码场景是获客入口，不能设登录墙）

###

- 前端仅做简单正则规则识别（判断字符串是否长得像口令码，用于决定要不要发请求）

- 正式识别（解析用户名 + 匹配榜单）在**后端完成**
- 静默识别 onShow 每次会发请求，后端需评估压力（继超判断可接受）

- 未登录用户手动输入的口令码识别请求也需支持（无需鉴权可访问榜单读接口）

## 后端依赖

- 口令码生成算法（形容词随机选取 + 随机字母组合，确保唯一性）

- 口令码校验/查询接口

- Phase 1 已有榜单批量补生成口令码

设计需求

榜单编辑页分享 icon + 半屏分享弹窗布局（三种分享方式）、手动输入口令码半屏弹窗（含 input 框 + 开始识别按钮 + 查看口令码规则链接）、口令码规则中心弹窗、首页左上角「识别口令」按钮、隐私保护说明弹窗（如需）。Figma 设计稿已完成（Epic 6），需根据 7.12 修订版 PRD 更新设计稿。
