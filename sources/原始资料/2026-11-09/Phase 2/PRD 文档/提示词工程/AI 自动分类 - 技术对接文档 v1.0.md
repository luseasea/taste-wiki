# AI 自动分类 - 技术对接文档

版本: v1.0 | 日期: 2026-07-19 | 技术方案: Embedding + 向量相似度

---

## 1\. 功能概述

用户通过「添加Tab → 新建条目」时，系统根据条目名称和内容，**自动判断该条目归属哪个分类**（玩乐/美食/好物/其他），无需用户手动选择分类。

---

## 2\. 触发范围

### 2.1 三渠道对照

| 新建渠道 | 是否触发 AI 分类 | 归类逻辑 |
| --- | --- | --- |
| **添加Tab → 新建条目** | ✅ 触发 | AI 根据条目内容自动判断四分类 |
| 文件夹内页 → 新建条目 | ❌ 不触发 | 直接归入当前文件夹的分类 |
| 榜单编辑页 → 新建条目 | ❌ 不触发 | 归入当前榜单的类别 |

### 2.2 为什么只在「添加Tab」触发？

因为此时用户**没有上下文**——不在某个文件夹里，也不在某个榜单里。系统不知道该归到哪一类，所以需要 AI 来判断。

另外两个渠道：用户已经在玩乐文件夹里了 → 新建的自然就是玩乐；用户在美食榜单里 → 新建的自然就是美食。不需要 AI。

## 3\. 四分类定义

| 分类 | 图标 | 一句话定义 | 典型示例 |
| --- | --- | --- | --- |
| 美食 | 🍽️ | 可以吃/喝的东西和场所 | 餐厅、咖啡馆、奶茶店、火锅、甜品、食材 |
| 玩乐 | 🎯 | 娱乐体验、运动旅行、活动场所 | 景点、展览、演出、健身房、密室逃脱、KTV |
| 好物 | 🛍️ | 实体商品、物品、产品 | 电子产品、书籍、服饰、美妆、家居、文创 |
| 其他 | 📦 | 以上三类都归不进去的 | App、服务、人物、影视、数字内容、音乐 |

### 3.1 边界判定规则

以下是容易产生歧义的场景，需要特别注意：

| 易混淆场景 | 正确归类 | 判断逻辑 |
| --- | --- | --- |
| 咖啡店 / 奶茶店 / 酒吧 | 美食 | 核心是可饮用产品，吃喝为主 |
| 猫咖 / 狗咖 | 玩乐 | 核心是互动撸猫，饮品是附属 |

| 书吧 / 图书馆（空间体验） | 玩乐 | 本质是阅读空间，不是买书 |
| 火锅底料 / 食材 | 美食 | 食材 = 美食 |
| 厨具 / 餐具 / 锅具 | 好物 | 工具 = 好物 |
| 健身房 / 私教课 / 瑜伽 | 玩乐 | 运动体验 |
| 运动鞋 / 运动手环 / 瑜伽垫 | 好物 | 实体商品 |
| 演唱会 / 音乐节 / Livehouse | 玩乐 | 演出活动 |
| 专辑CD / 黑胶唱片 | 好物 | 实体商品 |
| 数字专辑 / 音乐App（QQ音乐） | 其他 | 数字内容 / 服务 |
| 盲盒 / 手办 | 好物 | 实体商品 |
| 泡泡玛特门店 | 玩乐 | 进店抽盒是体验，大于购买本身 |
| 外卖App（美团外卖） | 其他 | 平台服务，不是具体食物 |
| 宠物店（撸猫/洗护） | 玩乐 | 互动体验 |
| 宠物用品 | 好物 | 实体商品 |
| 电影 | 其他 | 数字内容 |
| 电影院 | 玩乐 | 体验场所 |

### 6.2 锚点向量

**原理**：每个分类预先定义一组「锚点文本」（能代表该分类语义的关键词和短句），对这些文本做 Embedding 后取均值，得到该类别的中心向量。新条目来了之后，计算条目向量和四个中心向量的相似度，取最高的。

**四分类锚点文本：**

**美食：** 餐厅、美食、小吃、饮品、咖啡、奶茶、甜品、火锅、烧烤、日料、西餐、中餐、酒吧、烘焙、食材、料理、面馆、快餐、自助餐、大排档

**玩乐：** 景点、展览、演出、音乐会、运动、健身、徒步、旅行、游乐园、密室逃脱、剧本杀、KTV、电影院、博物馆、公园、海滩、登山、滑雪、潜水

**好物：** 商品、电子产品、书籍、服饰、美妆、家居、数码、文创、手办、香水、包包、手表、首饰、家电、文具、玩具、礼品、日用

## 7\. 置信度阈值与兜底

| 条件 | 处理方式 |
| --- | --- |
| 最高相似度 ≥ 0.75 | 直接归类，正常返回 |
| 0.50 ≤ 相似度 \ | 归入该类，但标记为低置信度（前端暂不提示用户，后续迭代可增加确认弹窗） |
| 相似度 \ | 归入「其他」兜底 |
| 最高两类分差 \ | 视为模糊——两个类别都很像，归入「其他」兜底 |
| Embedding 调用失败 / 超时 | 归入「其他」+ 后台记录告警日志 |

> **说明**：阈值（0.75 / 0.50 / 0.10）为初始值，上线后根据实际数据表现可调整。

## 8\. POI 辅助规则
POI 信息**已通过 §4.2 的输入模板直接拼入了 Embedding 文本**，模型会自行学习位置与分类的语义关联。

在此基础上，可以额外叠加以下**硬规则加权**（可选实现，建议 v1 先不加，观察 Embedding 效果后再决定）：

| POI 类型关键词 | 倾向分类 | 置信度加成 |
| --- | --- | --- |
| 美食街 / 美食广场 / 大排档 / 餐饮 / 食堂 | 美食 | +0.15 |
| 购物中心 / 商场 / 百货 / 奥特莱斯 / 步行街 | 好物 | +0.10 |
| 景区 / 公园 / 游乐园 / 博物馆 / 体育馆 / 剧院 | 玩乐 | +0.15 |
| 写字楼 / 产业园 / 机场 / 高铁站 / 小区 | 无倾向 | 0 |

### 8.1 POI 核心价值场景

同一条目名称在不同 POI 下可能归入不同分类。这是 POI 最有价值的场景：

| 条目名称 | POI | 归类 | 原因 |
| --- | --- | --- | --- |
| 全家便利店 | 北京·朝阳·国贸写字楼B1 | 美食 | 写字楼便利店以快餐/便当为主 |
| 全家便利店 | 广州·番禺·祈福新村小区内 | 好物 | 小区便利店以日用品为主 |

用户可以在条目详情页手动将条目「移动」到其他分类。每一次手动移动 = 一次纠错信号，用于持续优化分类效果。

### 9.2 更新策略

| 规则 | 说明 |
| --- | --- |
| 不实时更新 | 单次纠错不立即更新锚点向量，防止噪声 |
| 批量更新 | 每累计 **20 次**同类纠错后，将该批条目向量加入正确分类的锚点集合，重新计算该分类的均值向量 |
| 异常过滤 | 同一用户短时间内大量纠错（如1小时内>50次）→ 标记异常，不参与训练 |
| 更新频率 | 建议每天凌晨离线跑一次，非实时 |
