# AI 智能推荐 - 提示词

版本: v1.0 | 日期: 2026-07-19 | 技术方案: LLM (DeepSeek) + Prompt Engineering

---

## 一、功能概述

用户在创建/编辑榜单时，根据**榜单标题 + 类别 + 已入选条目**，从用户条目库中智能推荐匹配的条目，帮助快速填充榜单。推荐结果与手动选择可在同一弹窗内混合编排。

### 合规要求（去 AI 化，前端不涉及任何“ai”相关表述）

### 技术方案

| 项目 | 说明 |
| --- | --- |
| 模型 | DeepSeek（或其他国产大模型） |
| 调用方式 | 云端 API，后端代理（小程序不直接调用） |
| 成本 | \~240 元/年 |

---

## 二、触发入口

| \# | 入口 | 场景 |
| --- | --- | --- |
| 1 | 榜单编辑页 → 左下角「添加」→ 半屏弹窗「从条目库选择」Tab | 主要场景 |
| 2 | 创建榜单页（B情况）→ 待评级区上方横条「试试智能推荐...」 | 复制后创建时引导 |

> 入口 2 仅在 US-29 B 情况出现；A/C 情况无推荐入口。

## 三、输入信号

| 信号 | 类型 | 说明 |
| --- | --- | --- |
| 榜单标题 | string | ≤20字，如「广州必喝咖啡馆 TOP10」 |
| 榜单类别 | enum | 玩乐 / 美食 / 好物 / 其他 |
| 已入选条目 | array | 当前待评级区条目（名称 + 描述 + POI），用于**排除** |
| 条目库 | array | 用户条目库中**与榜单类别相同**分类的条目（如榜单是美食 → 只传美食库） |

### 条目库传入控制

| 条件 | 处理 |
| --- | --- |
| 对应分类条目 ≤ 300 条 | 全部传入 |
| \> 300 条 | 随机采样至 300 条 |
| 每个条目传入字段 | item\_id、name、description（截断至 50 字）、category、poi |

### 推荐限制

- 上限 20 个，下限无（宁缺毋滥）

- 排除已入选条目

## 六、🤖 Few-Shot 示例（重点）

### 示例 1：正常推荐 + POI 地理约束

**输入：**

- 榜单：广州天河区必喝咖啡馆 TOP10 | 美食

- 已选：急急脚咖啡公司 | 📍广州·越秀·东山口

- 条目库：


 \[01] .jpg咖啡 | 精品手冲 | 📍广州·天河·体育西路 | 美食

 - \[02] M stand | 工业风咖啡 | 📍广州·天河·珠江新城 | 美食

 - \[03] %Arabica | 京都网红咖啡 | 📍深圳·南山·万象天地 | 美食

 - \[04] The Dose | 复古意式 | 📍广州·越秀·北京路 | 美食

 - \[05] 海底捞 | 火锅 | 📍广州·天河·体育西路 | 美食

**期望输出：**

**分析：**

- 01 (.jpg咖啡) 最高分：天河区 ✅ + 咖啡馆 ✅

- 02 (M stand) 高分：天河区 ✅ + 咖啡馆 ✅
- 04 (The Dose) 降权：越秀区≠天河区，但同城仍推荐

- 03 (%Arabica) **不推荐**：深圳≠广州，跨城硬过滤 ❌

- 05 (海底捞) 不推荐：火锅与咖啡不相关

### 示例 2：遛娃榜单（无已选条目）

**输入：** 榜单「深圳周末遛娃好去处」| 玩乐 | 无已选 | 条目库 7 条（含深圳湾公园、深圳博物馆、欢乐海岸等）

**期望输出：** 深圳博物馆(0.90) → 仙湖植物园(0.89) → 欢乐海岸(0.86) → 深圳湾公园(0.78)

**关键：** 理解「遛娃」= 亲子+小孩友好，而非泛玩乐

### 示例 3：无匹配

**输入：** 榜单「我最喜欢的日本动画电影」| 其他 | 条目库仅火锅店、景点、耳机

**期望输出：** `{"recommendations": [], "total_candidates": 3, "recommendation_count": 0}`

## 七、前端展示与状态

| 场景 | 行为 |
| --- | --- |
| 加载中 | 条目卡片逐个弹出（staggered reveal），底部按钮「智能推荐中...」置灰 |
| 有结果 | 底部分别显示「添加至待评区（N）」和「不满意？前往条目库手动选择更多」 |
| 无结果 | 空状态插画 + 「条目库无匹配项」+ 「前往条目库手动选择」按钮 |
| 超时（>5s） | 降级：「推荐暂时不可用」，仅保留手动选择入口 |
| 接口报错 | 同上，静默降级，不弹 toast |

## 八、手动选择分支与数据联动

点击「不满意？前往条目库手动选择更多」→ 进入全屏手动选择页：

- **页面结构**：与条目库首页相同，但**去掉**顶部头像/识别口令按钮 + 底部导航栏，仅保留四分类文件夹

- **多选态**：与 US-26 批量操作不同，底部仅一个按钮「添加到榜单」（无移动/删除）

- **数据联动（核心）**：推荐弹窗中已勾选的条目 → 在手动选择页对应文件夹内**自动显示为已勾选**；用户可取消、可额外勾选

- **回到弹窗**：手动条目前置（普通边框），推荐条目后置（炫彩边框），去重后合并展示
- **可多次往返**：每次累加手动条目，回到弹窗时自动重排

## 九、待评级区最终处理

| 变化 | 说明 |
| --- | --- |
| 弹窗关闭 | 条目进入待评级区 |
| 彩色边框去掉 | 进入后所有条目一视同仁，不区分来源 |
| 排列顺序 | 与弹窗内一致（手动在前，推荐在后） |
| 不重复添加 | 待评级区已有该条目则跳过 |

## 十一、缓存策略

| 触发条件 | 行为 |
| --- | --- |
| 同榜单（标题+类别+已选条目）未变化 | 5 分钟内走缓存 |
| 增删已入选条目 / 修改标题或类别 | 清除缓存，重新请求 |
| 条目库有新增条目 | 清除缓存（候选池变了） |

## ⚙️ 参数说明

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 模型 | DeepSeek-V2 | 可替换为其他国产模型 |
| Temperature | 0.3 | 低温度保证输出稳定 |
| Max Tokens | 2048 | 足够输出 20 个结果 |
| 推荐上限 | 20 | 单次最多推荐 |
| 条目描述截断 | 50 字 | 传给模型的描述最大长度 |
| 条目库采样上限 | 300 | 超出则随机采样 |
| 缓存时长 | 5 分钟 | 同榜单重复请求缓存 |
| 超时时间 | 5 秒 | 接口超时阈值 |
