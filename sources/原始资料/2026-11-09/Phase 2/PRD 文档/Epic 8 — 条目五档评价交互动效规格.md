## 二、触发阶段

| 参数 | 规格 |
| --- | --- |
| 按压时长 | ≥ 400ms 触发长按 |
| 400ms 时 | 条目卡片轻微震动（`vibrateShort` 15ms）+ 页面其余区域开始出现白色毛玻璃遮罩 |
| 500ms 时 | 遮罩到位 + 卡片浮升居中 + 五选项弹出 |

**触发失败边界**：

- 按压 \ 10pt → 进入拖动排序（编辑态）或忽略（查看态）

## 三、毛玻璃遮罩

### 3.1 规格

| 属性 | 值 |
| --- | --- |
| 背景色 | `rgba(255, 255, 255, 0.72)` 白色半透明 |
| 模糊 | `backdrop-filter: blur(20px)` |
| 饱和度 | `saturate(1.1)`（轻微增强，保留底层内容色调） |
| 入场动效 | 不透明度 0 → 1 + 模糊度 0 → 20px，同步过渡 |
| 入场时长 | 250ms ease-out |
| 离场动效 | 不透明度 1 → 0 + 模糊度 20px → 0，同步过渡 |
| 离场时长 | 200ms ease-in |
| z-index | 低于条目卡片、高于页面其余内容 |

### 3.2 小程序实现说明

微信小程序 `backdrop-filter` 兼容性有限（基础库 ≥ 2.9.0 支持但部分安卓机型有性能问题）。降级方案：

- **优先**：`backdrop-filter: blur(20px)` + `-webkit-backdrop-filter: blur(20px)`
- **降级**：纯白色半透明遮罩 `rgba(255,255,255,0.85)`（去掉模糊，加高不透明度补偿）

- **检测方式**：`wx.canIUse("css.backdrop-filter")` 判断，不可用时自动降级

## 四、卡片浮升居中

| 步骤 | 动效 | 时长 |
| --- | --- | --- |
| 卡片浮升 | scale 1.0 → 1.05，阴影 elevation +12pt | 250ms ease-out |
| 视觉居中 | 卡片移动到屏幕视觉中心（向上偏移 10% 补偿拇指遮挡） | 300ms ease-out |
| z-index | 卡片 z-index 抬至最顶层（高于遮罩和选项） | 瞬时 |

视觉中心计算公式：

- x = 屏幕宽度 / 2

- y = 屏幕高度 / 2 − 屏幕高度 × 0.10

## 六、自适应展开方向

根据被长按条目卡片的原始屏幕位置，决定环形开口朝向，确保选项不超出屏幕边界。

### 6.1 判定逻辑（优先级从高到低）

**第一步 — 检查边缘贴合**：
| 条件 | 行为 |
| --- | --- |
| 卡片左边距 \ | 半圆向右展开，左侧闭合 |
| 卡片右边距 \ | 半圆向左展开，右侧闭合 |
| 卡片顶边距 \ | 环形向下偏移，上方闭合 |
| 卡片底边距 \ | 环形向上偏移，下方闭合 |

**第二步 — 检查四角**（边缘检查通过后叠加角修正）：

| 条件 | 行为 |
| --- | --- |
| 卡片在左上角（x \ | 四分之一圆，向右下展开 |
| 卡片在右上角（x > W-60pt 且 y \ | 四分之一圆，向左下展开 |
| 卡片在左下角（x \ H-80pt） | 四分之一圆，向右上展开 |
| 卡片在右下角（x > W-60pt 且 y > H-80pt） | 四分之一圆，向左上展开 |

**第三步 — 默认**（不满足以上任何条件）：

- 完整 270° 环形，下方开口留空

### 6.2 边界安全距离

选项最外沿与屏幕边缘之间的最小安全距离：**16pt**。计算环形半径时动态修正。

## 七、滑动选择交互

### 7.1 判定逻辑

手指不离屏，实时计算手指位置与五个选项中心的欧氏距离。最短距离 \ 25pt） | 选项恢复 scale 1.0，发光消失，等级名消失 | 无 | 120ms ease-out |
| 跨选项滑动 | 上一选项缩回 + 下一选项放大，无缝衔接 | 每次进入新选项轻震一次 | 120ms |

## 八、确认选择

### 8.1 松手确认

手指在某个选项上松手即确认选择。动效时序：

| 步骤 | 描述 | 时长 |
| --- | --- | --- |
| 1\. 蓄力 | 选中选项 scale 1.35 → 0.85 → 1.0（按压感） | 150ms |
| 2\. 爆发 | Emoji 组合从选项中心向目标方向喷射 | 0ms 触发 |
| 3\. 其他选项消失 | 四个未选项 fade out + scale 0.5，缩回中心 | 200ms |
| 4\. 遮罩消退 | 毛玻璃遮罩 1→0 + 卡片 scale 1.05→1.0 | 250ms |
| 5\. 残留标记 | 条目卡片上出现本次选择的 Emoji 主图标小圆点 | 与步骤4同步 |

## 十五、边界场景

| 场景 | 行为 |

## 十六、前端实现指引

1. **毛玻璃遮罩**：优先 `backdrop-filter: blur(20px)`，`wx.canIUse` 检测降级
1. **Emoji 动效引擎**：建议封装 `EmojiBurst` 组件，接收参数（emojiList, direction, gravity, duration）

1. **环形布局**：用三角函数计算五个圆心坐标，圆心 = 卡片中心 + (radius × cos(angle), radius × sin(angle))

1. **滑动检测**：`touchmove` 事件中实时计算手指与五个选项中心的欧氏距离 `√((x1-x2)² + (y1-y2)²)`

1. **性能注意**：Emoji 粒子数量少（每次3个），无需 Canvas，可用 `transform` + `transition` 实现 GPU 加速

## 附录：与查看者小球可视化的衔接

本规格覆盖的是**表态输入侧**（长按→评分）的交互。

表态完成后 → 查看者看到的是物理小球可视化（参考 Epic 8 PRD v2.0 US-29 查看者视角）。小球颜色使用用户所选的五档颜色，用户头像 + 颜色边框。

两者衔接点：**残留标记**（条目卡片上的 Emoji 小圆点）是输入侧到展示侧的过渡元素——提醒用户「你已评价过这个条目」。

## 十七、彩带飞溅效果（Emoji 爆发引擎 v2）

> ⚠️ 本章节取代第九节「Emoji 爆发动效引擎」，以本章为准。

### 17.1 设计原则

- 爆发原点：**被评价条目的卡片中心**（非选项位置）

- 爆发时机：手指在选项上松手确认后，150ms 蓄力 → 爆发

- 运动介质：每个等级对应 2-3 个 Emoji，从条目中心向四周飞散

- 视觉意图：夯和拉的 Emoji 故意反着来——夯（最差）用庆祝表情制造滑稽反差感，拉用排斥表情直白表达嫌弃

---

### 17.2 等级动效总览

| 等级 | Emoji 组合 | 运动模式 | 运动方向 | 设计意图 |
| --- | --- | --- | --- | --- |
| 🟤 夯 | 👑 🎉 🐂 | 螺旋上升 Spiral Upward | 从中心顺时针螺旋向外上升 | 反讽庆祝——越差的越送上皇冠和牛，制造幽默反差 |
| 🟠 拉 | 💩 🙅‍♀️ 🙅‍♂️ | 自由落体 Fall Down | 从中心向下方坠落 + 轻微左右飘荡 | 直白嫌弃——屎和拒绝手势，毫不遮掩 |

### 17.7 实现指引

**1. 轨迹计算**：水平位移 `x(t) = x0 + vx*t + A*sin(omega*t)`，垂直位移 `y(t) = y0 + vy*t + 0.5*g*t²`

**2. 螺旋模式（夯）**：极坐标 `r(t) = r0 + vr*t`，`theta(t) = theta0 + omega*t`，转笛卡尔 `x = r*cos(theta)`，`y = r*sin(theta)`

**3. 扇形模式（顶级）**：三个 Emoji 初始角度分别为 -60°/0°/+60°（向上 120° 扇形范围），各自直线运动

**4. 振翅模式（🦋）**：在扇形的直线轨迹上叠加正弦波偏移 `offset = A*sin(omega*progress)`，偏移方向垂直于飞行方向

**5. 弹跳模式（💩）**：落地判定 `y >= y_target` 时速度反向乘 0.3（能量损失），`y = y_target - |v|*0.3*t + 0.5*g*t²`

**6. 性能**：所有 Emoji 用 `&lt;text>` 渲染（非 Canvas），`transform` + `opacity` 做 GPU 加速动画
