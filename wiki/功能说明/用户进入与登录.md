# 用户进入与登录

> FEAT-008｜整理：2026-11-10｜状态：需求资料摘要，待审核；逐项实现与上线未核实｜审核人 / 时间：尚无。

## Phase 1 的两条入口

| 场景 | 该版本 PRD 的设计 |
| --- | --- |
| 主动搜索首次进入 | 品牌欢迎约 1.5 秒 → 两屏玩法引导，可跳过 → 我的榜单空态 |
| 再次打开 | 直接到我的榜单，不重复首次引导 |
| 朋友分享进入 | 直接看榜单完整内容，无需先登录；想创建时再触发登录 |

个人信息设置包括头像、昵称和条款同意；“登录并进入”需要三个条件满足，昵称限制 10 字以内。登录失败提示重试。这里是 Phase 1 PRD 的要求，不据此保证当前授权组件仍与原设计完全相同。

## 用户角色

查看者先消费分享内容，创建者才需关联自己的数据。创建者看到可编辑榜单；查看者只读，头像昵称用于说明是谁推荐，不设个人主页跳转。分享进入后的具体交互见 [微信分享与查看](微信分享与查看.md)。

## Phase 2 的变化及冲突

Epic 7 要求个人写入操作登录后返回原目标；口令手动识别不设登录墙。各自见 [新建与浏览](条目新建与浏览.md)、[口令识别](口令识别与传播.md)。

未登录点击条目入口究竟直接登录还是先展示引导空态，两份来源不一致，保留 [Q-010](../../questions/待确认事项.md#q-010-未登录进入条目库的行为不一致)。不得用 Phase 1 流程覆盖 Phase 2 新场景，也不因后续 PRD 存在就宣布替换了线上。

## 原始讨论与版本

早期业务问答提出先看价值再登录；Phase 1 PRD 的 v1.3 变更记录细化三条件个人信息页与首次引导。讨论表中的建议、用户确认和后来规格需要分别阅读，不能将表中所有建议都算已确定。
